## _MENESTREL_

> README criado originalmente por murilo-tsu; edições e revisões posteriores feitas com o auxílio do Claude.

O *Menestrel* é um orquestrador de scripts para a extração de relatórios do SAP4HANA via SAP GUI Scripting. Roda continuamente numa VM Windows com SAP GUI instalado, navegando as transações no lugar de um usuário humano, exportando os relatórios para Excel e subindo os arquivos para o MinIO — que serve como camada *stage* de entrada de dados para o pipeline (Airflow/Hadoop) consumido pelo time de Data Insights.

### Escopo

- **Ponto de entrada**: `dag_trigger/menestrel.py`. Mantém um loop (`schedule.run_pending()`, a cada 10s) que dispara três grupos de tarefas:
  - **Extração diária** (`extracao_diaria`, 00:05): batelada sequencial de 25 tarefas — `POSITION_FILES` → `SKU` → `WERKISH` → `CUSTOS` → `FATURAMENTO` → `BOM` → `COMPRAS` → `COCKPIT` → `VBAK` → `GL_ACCOUNTS` → `INDIRECT_PROCUREMENT` → `ESTOQUE` → `MB51_QUEBRA` → `FBL1H` → `COOISPI_SEG` → `COOISPI_VARREDURA` → `COOISPI_VARREDURA_MP` → `ZFI_NF_PIVB` → `VL06I` → `COGI` → `ZFI_GL_PIVB` → `MB51_CONSUMO` → `FBL3H` → `FBL5H` → `NF_01` — seguida do disparo da DAG `daily_chained_dags` no Airflow. Tarefas isoladas em horários fixos fora dessa cadeia: `TEXT_INFO` (05:00) e `ESTOQUE_FULL` (19:05 — deliberadamente logo após o fechamento da janela incremental, ver abaixo).
  - **Extrações incrementais** (`executar_incrementais`): reagendamento dinâmico, não um poll de intervalo fixo — `armar_incrementais` se rearma todo dia às 00:15 e a cada hora cheia dentro da janela **06:00–19:00**, garantindo que a primeira checagem do dia caia bem no início do slot (06:00). A partir do primeiro disparo, roda de hora em hora até as 19:00. Desativadas aos domingos. Estrutura adotada do `dag_trigger_vFH`: sem janela de horário individual por task (a janela única 06:00–19:00 já cobre todas), as 6 tasks (`FATURAMENTO`, `COMPRAS`, `GL_ACCOUNTS`, `INDIRECT_PROCUREMENT`, `ZMB5T`, `MB52`) rodam em todo tick e seus resultados vão para um dicionário; ao final, dispara **uma única** DAG combinada (`minio_incremental_hourly`) no Airflow se pelo menos uma tiver tido sucesso — não mais um trigger individual por task. `ESTOQUE_FULL` roda às 19:05, fora dessa janela por construção, evitando que seu tempo de execução (iteração diária por data × BUKRS, potencialmente longa) colida com o corte `.until(19:00)` do último tick incremental do dia.
- **Cada script `engdds_*.py`** (em `dag_trigger/`) automatiza uma transação SAP específica via `win32com`/SAP GUI Scripting, usando `saplogin.py` (classe `SAPLogin`) para login/logout e `Minio.py` para subir o Excel exportado ao bucket de stage. Todos seguem o mesmo padrão de exportação `&XXL`: `sap.kill_excel()` antes de cada exportação (mata `excel.exe` órfão de uma iteração anterior) envolvido por `sap.export_watchdog(timeout=180)`, que mata o Excel por fora se a chamada travar além de 180s. O login em si (`sap.login_to_s4hana()`) é protegido por `sap.login_watchdog(timeout=120)`, que mata o `saplogon.exe` se o handshake de login travar — ambos os watchdogs rodam o `taskkill` numa thread separada sem tocar em objetos COM, então são seguros mesmo com a chamada SAP bloqueada na thread principal.
- **Restrição de concorrência crítica**: todo o scripting COM/SAP GUI roda na **mesma thread** — não há paralelismo entre tarefas. Um `threading.Lock` (`sap_lock`) garante que a extração diária e as incrementais nunca rodem simultaneamente.
- **Resiliência em camadas**: `run_with_retry` tenta cada tarefa do orquestrador até 2 vezes (60s de intervalo); dentro de scripts com granularidade mais fina (ex. `engdds_estoque.py`, que itera data × empresa/BUKRS), `executar_com_retry` faz o mesmo por item individual (3 tentativas, 60s), sem repetir combinações que já deram certo. Falha numa tarefa não interrompe as demais — a orquestração segue para a próxima. Tudo é logado em `menestrel_song.log`; as tarefas incrementais têm sua saída redirecionada também para `menestrel_verbose.log` (via `rodar_com_saida_verbose`), para manter o log principal legível sem perder detalhe de diagnóstico.
- **Watchdog externo** (`dag_trigger/watchdog_menestrel.py`): processo curto e independente, pensado para rodar via Task Scheduler a cada poucos minutos. Verifica se o PID em `menestrel.pid` ainda existe e se `menestrel_heartbeat.txt` (escrito a cada iteração do loop principal) não está parado há mais de 60 minutos — sinal de que uma chamada COM travou a thread única além do que os watchdogs internos conseguiram resolver. Se detectar processo morto ou heartbeat parado, mata o processo + satélites (`saplogon.exe`, `excel.exe`) e relança o `menestrel.py` do zero. Tem um hook opcional de notificação via webhook do Teams (`TEAMS_WEBHOOK_URL`), atualmente desativado.
